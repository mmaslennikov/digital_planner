
# Цифровой планировщик 

## 1. Описание проекта

Проект представляет собой систему планирования последовательности задач на одном процессоре (одном станке) с целью максимизации суммарной награды при ограничениях по времени выполнения задач.

Каждая задача имеет:
- `task_id` — идентификатор
- `time` — длительность выполнения
- `deadline` — крайний срок завершения
- `reward` — награда за выполнение в срок

Награда начисляется **только если задача завершена до дедлайна**: start_time + time <= deadline


## 2. Цель задачи

Необходимо найти такой порядок выполнения задач, который:

- максимизирует суммарную награду
- учитывает дедлайны
- учитывает невозможность параллельного выполнения задач (одна машина)



## 3. Реализованное решение

Есть несколько возможных решений: динамическое программирование, библиотечные решения на линейном программировании (например, pulp), решения на основе анализа ограничений (например, OR-Tools, CP-SAT), метод ветвей и границ, A*, лучевой поиск (beam search). Из-за небольшой размерности и для более интуитивного понимания проблемы, в первой части был сделан выбор в пользу самостоятельной реализации на основе динамического программирования.  

### 3.1 Алгоритм динамического программирования с отсечением состояний 

Сначала все задачи сортируются по дедлайнам

Затем используется динамическое программирование по состояниям: dp[time] = (max_reward, sequence_of_tasks)


Каждое состояние означает:
- достижимое суммарное время
- максимальную награду на этом времени
- последовательность выбранных задач

Для каждой новой задачи:
- либо не берём задачу
- либо добавляем её, если не нарушается дедлайн


### 3.2 Отсечение состояний

Для уменьшения количества состояний применяется оптимизация:

- состояния сортируются по времени
- удаляются доминируемые состояния:
  - если существует состояние с меньшим временем и большей или равной наградой, худшее состояние отбрасывается

Это позволяет:
- избежать перебора всех времён на отрезке `0..max_deadline`
- держать только "значимые" состояния

По сути, это эвристическое отсечение доминируемых состояний. Для размерностей тестового задания (сотни задач) данный подход показывает хорошую производительность, однако не гарантирует сохранение всех потенциально оптимальных состояний в общем случае.

### 3.3 Сложность

Пусть:
- `N` — число задач (до ~300–1000)
- `S` — число недоминируемых состояний (обычно сильно меньше N * deadline)

Тогда:
- худший случай: `O(N * S)`
- средний случай: близко к `O(N^2)`
- память: `O(S)`

На 300 случайных задачах получается результат:\

## 5. Формат входных данных

Файл `input.csv`:

```csv
task_id,time,deadline,reward
1,1,2,1
2,5,5,2
3,1,1,2
```

## 6. Формат выходных данных

Файл output.csv:
```csv
3,1
```
(последовательность task_id в порядке выполнения)

## 7. Запуск программы

### 7.1 Установка

Нужно установить Python. При отладке использовался Python 3.10.7

### 7.2 Запуск через CLI

```bash
python3 -m src.dp_solver io/input.csv io/output.csv
```

Вывод:
```bash
Найдено решение, в котором X задач
Расписание: 3,1,...
```

## 8. Тестирование
Запуск тестов
```bash
python3 -m unittest src.test_dp_solver
```
Типы тестов
1. Базовый тест

Проверка корректности на небольшом примере:

```
[1,1,2,1], 
[2,5,5,2], 
[3,1,1,2]
→ [3,1]
```

2. Стресс-тест (300 задач)

Проверяет:

- корректность результата
- уникальность задач
- принадлежность входным данным
- выполнение за разумное время

3. Тест на дедлайны

Проверяет, что алгоритм корректно учитывает ограничения времени выполнения.

4. Тест на награды

Проверяет, что алгоритм не игнорирует задачи с высокой наградой.

## 9. Архитектура системы
### 9.1 Solver interface

Все алгоритмы наследуются от:

```python
class Solver(ABC):
    def solve(self) -> list[int]:
        pass
```
Это позволяет:

- подключать новые алгоритмы
- заменять DP на pulp / CP-SAT / эвристики

## 10. Расширяемость (часть задания 2.2)
### 10.1 SuperSolver

SuperSolver — заготовка универсального планировщика.

Поддерживает:
- ограничения следования (task_i перед task_j)
- штраф за дедлайныdeadline penalties (reward - penalty)
- настраиваемые целевые функции (sum(reward) - sum(penalty))

### 10.2 Язык ограничений
Описывается через YAML:

task_precedence:
  - task_before: int
  - task_after: int

deadline_penalty:
  - penalty: float

target_function:
  - reward: float
  - penalty: float

### 10.3 Архитектура расширения

Система проектируется так, чтобы:

- добавлять новые ограничения без изменения DP Solver
- подключать разные backend-решатели:\
-- DP (текущий)\
-- MILP (PuLP / OR-Tools)\
-- CP-SAT (Google OR-Tools)\
